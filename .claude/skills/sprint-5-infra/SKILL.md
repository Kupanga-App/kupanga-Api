# Sprint 5 — Stockage S3 et e-mails fiables

Argument reçu : `$ARGUMENTS`

1. Lis `.claude/CLAUDE.md` (§6 Décisions, §7 Points ouverts) et **`AUDIT-INFRA.md`** (§1 stockage, §2 e-mails), puis **suis exactement** `.claude/sprint-workflow.md` pour chaque tâche (l'audit de référence de ce sprint est `AUDIT-INFRA.md`).
2. Vérifie que les Sprints 1 à 4 sont terminés (§5).
3. Règles propres à ce sprint :
   - **Aucune dépendance à un fournisseur** : ni à un serveur S3 (MinIO, RustFS, Garage, R2), ni à un fournisseur d'e-mails (Brevo…). Le choix se fait **uniquement par configuration**.
   - Aucune adresse e-mail, aucun sujet, aucun contenu ni jeton dans les logs (W10) ; erreurs réduites à la classe de l'exception et au code SMTP.
   - Les buckets privés le restent (P0-7) ; URL présignées 5 min.
   - Le comportement « rien n'est envoyé si la transaction est annulée » (B11) doit être conservé.

## Ordre des tâches et points d'attention

| Ordre | ID | Tâche | Points d'attention |
|---|---|---|---|
| 1 | `S1` | Stockage S3 portable | Remplacer `io.minio:minio` par le SDK AWS v2 (`software.amazon.awssdk:s3`, version figée) : `S3Client` (endpoint interne) + `S3Presigner` (URL publique, région fixée, `pathStyleAccessEnabled` configurable). Renommer le package `minio` → `stockage` (`MinioService` → `StockageService`, `MinioConstant` → `StockageConstant`) et mettre à jour tous les appelants et tests. Config neutre `stockage.{endpoint,url-publique,region,path-style,access-key,secret-key}` (variables `STOCKAGE_*`), plus de `minio.*` ni `app.url-mino`. **Plus aucun `setBucketPolicy`/`deleteBucketPolicy` à l'envoi** : création des buckets au démarrage (`ApplicationReadyEvent`), politique de lecture publique posée seulement si `stockage.gerer-politiques=true` (sinon gérée par le déploiement), et **contrôle au démarrage** qu'un bucket privé n'est pas lisible anonymement (log `ERROR`). Tests : client S3 simulé (Mockito) + au moins un test d'intégration sur le vrai serveur de CI |
| 2 | `S2` | Clés en base au lieu d'URL | Nouvelles colonnes de clé (`bien_images`, `utilisateurs`) + **migration Flyway** qui extrait la clé (dernier segment après `/<bucket>/`) des URL actuelles, quel que soit l'hôte (`minio-backend.duckdns.org`, `localhost:9000`…) ; URL construite à la lecture par les mappers (`BienMapper`, `UserMapper`…). `estUrlDuBucket` / `supprimerParUrl` / `urlAvatar` (B5) à adapter : le front envoie une clé ou une URL de notre domaine public, jamais une URL libre. **Photos de profil passées en bucket privé + URL présignée** (point RGPD ouvert §7) : vérifier tous les endroits où l'URL de l'avatar est servie (annonce publique, messagerie, back-office). **Demander à l'utilisateur** avant de supprimer les anciennes colonnes d'URL (garder une version de transition est possible). Impact front à signaler (durée de vie des URL d'avatar) |
| 3 | `S3` | RustFS en dev, CI et tests | Image `rustfs/rustfs` **figée par version** (vérifier la dernière 1.0.x stable et sa page de configuration : variables d'accès, port, sonde de santé) dans `docker-compose-dev.yml` et `.github/workflows/ci.yml` (remplace Chainguard MinIO). Script `deploy/stockage/copier-minio-vers-s3.sh` (`rclone sync` source → cible, vérification `rclone check`, sans secret en dur). Mettre à jour `docs/sauvegardes.md` §2 (MinIO → RustFS) et le README (schéma d'architecture) |
| 4 | `M1` | E-mails en SMTP générique | `spring-boot-starter-mail` ; interface `ExpediteurEmail` + `SmtpExpediteurEmail` (`JavaMailSender`, `MimeMessageHelper` multipart UTF-8, HTML **et texte brut**, pièces jointes PDF lues dans le stockage, `Reply-To` facultatif, `Message-ID` sur le domaine de l'expéditeur). DTO neutre `EmailSortant` à la place de `BrevoEmail` ; supprimer `BrevoEmailClient` et la config `brevo.*` ; config `spring.mail.*` + `email.{expediteur,nom-expediteur,repondre-a}` (cf. `AUDIT-INFRA.md` §2.2). Délais SMTP bornés (connexion 10 s, lecture/écriture 20 s). Tests avec un faux serveur SMTP (GreenMail, version figée, `test` scope) : en-têtes, encodage des accents, pièce jointe, texte brut. Mettre à jour `.env.dev` **uniquement si l'utilisateur le demande** (secrets) : sinon lui indiquer les variables à renseigner (Brevo : `smtp-relay.brevo.com:587`, identifiant et clé SMTP du compte Brevo) |
| 5 | `M2` | File d'envoi persistante (outbox) | Table `emails_sortants` (migration) et entité, cf. `AUDIT-INFRA.md` §2.3 (type, priorité, statut, tentatives, prochain essai, péremption, pièces jointes par référence). `EmailServiceImpl` **écrit la ligne dans la transaction de l'appelant** (remplace l'événement en mémoire `EmailAEnvoyer` ; hors transaction : écriture dans sa propre transaction). Envoyeur : lot borné `SELECT … FOR UPDATE SKIP LOCKED` (requête native), passage `EN_COURS` avec verrou de durée limitée (une ligne bloquée par un plantage est reprise), envoi **hors transaction**, puis `ENVOYE` ou nouvel essai (1 min, 5 min, 15 min, 1 h, 3 h, 6 h, 12 h, 24 h) ; 5xx SMTP définitif → `ECHEC_DEFINITIF` ; lien expiré → `PERIME`. Réveil après commit (`ApresCommit`) + `@Scheduled` toutes les 30 s (`@EnableScheduling`, désactivable en profil test). **Jetons** (reset, confirmation, signature) : ne pas les garder en clair après l'envoi (contenu effacé à `ENVOYE`, ou lien reconstruit à l'envoi). Purge : contenu à 30 j, lignes à 90 j. L'exécuteur `emailExecutor` en mémoire disparaît ou ne sert plus qu'au réveil. Tests : rollback → aucune ligne ; panne SMTP → nouvel essai planifié ; deux envoyeurs concurrents → un seul envoi (base réelle) ; péremption ; purge |
| 6 | `M3` | Broker | **Poser la question à l'utilisateur** (`AskUserQuestion`) en rappelant `AUDIT-INFRA.md` §2.3 : option A « outbox PostgreSQL seule » (recommandée tant qu'il n'y a qu'une instance) ou option B « outbox + RabbitMQ » (répartition entre instances, base du futur relais STOMP). Noter la décision en §6 de `CLAUDE.md`. **A** : extraire l'interface `FileEmails` pour permettre B plus tard, rien d'autre. **B** : `spring-boot-starter-amqp`, l'outbox publie (confirmations de l'éditeur activées) vers une file durable, consommateur qui envoie, files de nouvel essai à délai (TTL + dead-letter) et file d'échecs ; RabbitMQ figé par version dans le compose de dev et la CI ; l'outbox reste la source de vérité (statut mis à jour par le consommateur) ; l'application démarre et garde ses e-mails en base si RabbitMQ est absent |
| 7 | `M4` | Back-office des e-mails + alertes | Page `backoffice/emails` (Thymeleaf, conventions §4 de `CLAUDE.md`) : filtres par statut et type, pagination bornée, **adresse masquée** (`j***@gmail.com`), dernière erreur, bouton « Renvoyer » (POST + CSRF, remet `A_ENVOYER`, refusé pour un e-mail périmé), compteur d'échecs sur le tableau de bord. Log `ERROR` (→ Sentry, sans adresse) quand un e-mail `CRITIQUE` passe en `ECHEC_DEFINITIF`. Contrôle de connexion SMTP au démarrage (log `ERROR` si échec, démarrage non bloqué ; désactivé en test). Tests d'intégration du back-office (accès refusé sans session admin, renvoi) |
